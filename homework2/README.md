4. Исключения
  FleetError — базовый класс исключений;
InspectionError — ошибка при прохождении техосмотра;
DataError — ошибка при обработке некорректных данных.
Техосмотр отклоняет транспорт, если в его имени присутствует подстрока broken без учёта регистра. В этом случае кидается InspectionError.
Также проверяются:
отрицательное энергопотребление;
значение простоты вне диапазона от 1 до 10;
некорректный код умного замка;
переполнение журнала;
отсутствие замка с указанным инвентарным номером.
Во всех этих случаях кидается DataError с разными пометками что не так.
5. Шаблоны
Реализован шаблонный класс Registry<T, Cap> - реестр объектов до Cap элементов.
Его методы:
  add() - добавление элемента
  size() - получение количества элементов
  operator[] - доступ по индексу
  operator<< - перегрузка для вывода реестра
Шаблон используется в двух случаях - для создания журнала админа и для отслеживания истории выставления объектов на витрину.
1) Журнал админа - Registry<LogEntry, 100> - история операций добавления и удаления предметов из парка. Сохраняет дату, время и тип операции.
2) История витрины - Registry<std::string, 50> - записи id когда-либо выставлявшихся на витрине предметов.
6. Перегрузка операторов
   operator<< - для вывода предмета из инвентаря и для вывода шаблона
   operator< - для сравнения элементов по id
7. Креативная часть
   Был добавлен класс умного замка SmartLock - он имеет возможность обновлять его четырехзначный код - изначально при добавлении он имеет код "0000". В дальнейшем с помощью команды update_code можно менять код доступа к замку. Замок электронный, поэтому является как предметом инвентаря, так и потребителем энергии.
   Были реализованы системы отслеживания истории изменений в виде админского журнала и журнала витрины. Для просмотра информации были созданы команды admin_history и showcase_history
8. Изменения во взаимодействии с консолью
   Реализованы все команды из таблицы.
   Изменения формата команд:
   remove id date time
   add type date time ...   В этих командах соответственно после типа и id вводятся строки даты и времени. Формата у них нет, можно вводить как угодно, единственное, без пробелов.
   Новые команды:
   add lock date time id name energy - добавить умный замок
   admin_history - просмотреть журнал изменений парка
   showcase_history - просмотреть историю витрины
   update_code id code - присвоить замку с id новый код code. В случае отсутствия id в парке или при другом типе айтема кидаются dataError с различным описанием. При не том формате кода (4 символа) - то же самое.
